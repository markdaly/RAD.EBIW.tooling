## EBIW_25_Full_Workflow-DIMSE (13357), roles ENCOUNTER_MGR, IM, MOD, RESULT_AGGREGATOR (each "2 to realize")

Short description: "Encounter-based Imaging Workflow - Use Case 1 - DICOM MWL, and C-STORE, then Notification to Aggregator". Models RAD TF-1 47.4.2.1.2.
Special instructions: EM does EBIW_10 first; IM should also start an EBIW_90 instance ("a monitor will examine one [RAD-132] ORU from this test"). "The Result Aggregator is required to be a receiver for the [RAD-132] notify transaction. The Encounter Manager may optionally be a receiver." If EM supports RAD-132, IM should send to both.

|---|---|---|---|---|

| 40 | MOD -> IM | RAD-131 C-STORE | Req | store |
| 50 | IM -> RA | RAD-132 ORU^R01 | Req | notification of the new study |
| 55 | RA -> RA | ACK | Req | "The Results Aggregator acknowledges receipt of the ORU. This is "Original Acknowledge Mode"." |
| 60 | IM -> EM | RAD-132 ORU^R01 | Opt | if EM supports RAD-132 |
| 65 | EM -> EM | ACK | Opt | same |

Monitor evaluation, verbatim where it binds:
- "In other EBIW tests, the monitor will closely examine the contents of the messages exchanged, so the monitor should not duplicate that work here." Focus is interoperability and workflow: observe, and check a few key attributes flowed EM -> Modality -> IM -> RA.
- Steps 20-40: watch the operator query, acquire, send; "there is nothing for the monitor to 'verify' here".
- Steps 50/60: at the RA, "you should observe that it does something more than just sending an ACK" (viewing, DB entry, status change). Verify these worklist attributes are in the RA's patient record: "Patient ID, including assigning authority (from PID-3 in the ORU); Patient Name (from PID-5); Accession Number, including assigning authority (from OBR-18); Study Instance UID (from OBX-5); Procedure Code (from OBR-4)".
- Steps 55/65 ACK: MSH + MSA; "MSA-1 Acknowledgement Code: value should be AA (Application Accept); in error cases it would be AE (Application Error) or AR (Application Reject). MSA-2 Message Control ID: contains the message control ID from MSH-10 in the incoming ORU. (The monitor does not have to check that these values match.)"
